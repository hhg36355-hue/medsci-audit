# challenge —— 检测器的植缺陷自检夹具

跑：`python run_challenge.py --python /path/to/python`（Windows 建议 `PYTHONUTF8=1`）

**共 27 个用例，覆盖 8 个检测器**：

- 2026-07-30 第三批**移植**的四个（`check_scope_coherence` / `check_confounding_completeness`
  / `check_binning_consistency` / `check_rounded_delta`），11 个用例，验收标准四格全过：
  中文植缺陷会开火、中文干净稿静默、英文夹具回归不被打坏、`--strict` 退出码符合设计。
- 2026-08-09 新增的四个**原创**统计表格检测器（`check_regression_table` / `check_ratio_columns`
  / `check_diagnostic_metrics` / `check_correlation_table`），16 个用例。**这批的夹具正文不是
  构造的假例子，而是当天逐篇复算 12 篇真实中文论文时实际抓到的错误**（李昕2024 表4 的
  OR 列 17 行错 14 行、胡根生2024 的比值列 15/16 行等于均值之商、胡小玲2025 的 17 个事件
  报灵敏度 72.00%、诸国华2021 的 TC 行 P 与自己的 CI 差 4 倍……），干净稿则取自同批复算
  **全对**的表（徐正文2024 表4、张丽丽2026 表3/表4），专门用来防过报。

**什么时候必须重跑**：同步上游之后、改这些脚本的任何正则或容差之后、以及把它们用于
真实投稿稿件之前。

## 夹具本身也被验证过（两次）

### 2026-08-09：新增四个检测器的反向验证

逐个把四个新检测器的**核心判据**替换成永不成立的条件，跑夹具确认对应用例 FAIL，
再按备份还原并复核 MD5（四个脚本还原后 MD5 全部回到基线、哨兵串残留 0）。

**过程里第一次没通过，值得记下**：打断 `check_correlation_table` 的 `R_P_MISMATCH` 时，
我只改了「p 为点值」那条分支，而该判据还有「p 报成 `<0.001` 界值」的另一条分支仍在开火，
于是夹具**照样全绿**。当时若就此收工，会得出"这个夹具是摆设"的错误结论——恰恰相反，是
我植的缺陷不够决定性。改成打断整个判据循环后，夹具立刻 FAIL。

**这与 2026-07-30 那次踩的是同一个坑**（见下），说明它不是偶然：**凡一个 verdict 有多条
产出路径，只打断其中一条就不构成决定性打断**。写反向验证时先数一遍该 verdict 有几处 `append`。

## 夹具本身也被验证过（2026-07-30）

按 CLAUDE.md「新写的门禁第一次就全绿 = 可疑」，本夹具做过一次反向验证：把
`check_scope_coherence.py` 里 `PROGNOSTIC_VERB` 的整段中文分支替换成一个永不匹配的哨兵串，
`run_challenge.py` 立刻报 `FAIL scope_coherence 中文·植缺陷`（退出码 1），而同一轮里
`英文·回归` 一用例仍 pass——说明夹具确实在测中文口径、且能区分中英两条路径。随后按备份
还原，MD5 复核回到 `61c2f7f6ed45a16948fc986bee20daa6`，哨兵串清零。

**过程里的一条教训（值得记住）**：第一次植入的缺陷**不够决定性**——只把
`预测(?:未来|远期|…)` 一个分支改成哨兵，而夹具正文里那句"建议每年复查心脏超声以监测疾病进展"
仍能命中 `(?:定期|每年…)(?:复查|随访|监测)`、`监测疾病`、`疾病进展` 三条其他分支，于是
夹具**仍然全绿**。当时若就此收工，得到的结论会是"夹具是摆设"——恰恰相反，是我植的缺陷
不足以让检测失效。**植缺陷验证的前提是这个缺陷真能让被测判据彻底失效**；否则"仍然全绿"
既不能证明夹具有效、也不能证明它无效，是一条无信息的观察。
